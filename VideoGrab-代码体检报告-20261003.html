一、已当场修掉的三条（出包 v1.0.200）

① 共享白名单漏了 .part —— 这是我 v1.0.199 自己引入的回归 已修

v1.0.199 我给共享加了扩展名白名单，但**漏了 part**（升级前下好的任务，分片还叫 seg_000001.part， 边下边播正是靠它）以及 webm/mkv/avi/flv/3gp/heic/bmp/tiff/svg。 后果：边下边播对那些老任务直接 403、这些格式的下载物在共享页/WebDAV 里直接消失。 现在白名单以 kindKey 那张分类表为准 + part/m4s/m3u8 三样播放必需项； 并加了一条跨表结构断言（"白名单必须覆盖 kindKey 全部扩展名"）—— 这条断言本来就能提前拦住我。

② 压缩失败会删掉源文件 已修 — 核实：CompressQueue.swift 里 retire(item) 原本写在 do/catch 之后、无条件执行，而 retire 会删 ownsSource 的源。

后果：压失败/取消 → 源没了 → 没法重试；更糟的是从「文件」App 选来的源是搬进来的 （CompressSheet.takePicked 这条入口是可达的），删了等于删掉唯一副本—— 而 Compressor 文件头自己写着"绝不自动删原片"。现在 retire 只在压成功那条路走。

③ 外部选来的源"先搬后拷" → 可能搬走用户原件 已修

原逻辑：不在 App 目录的文件先 moveItem，失败才拷贝。从「文件」App 选来的可能是用户原件， 搬走等于把他原来位置的文件删了。现在：只对系统临时目录里的副本用搬，其余一律只拷贝。

五、说明：我按项目现实过滤掉了哪些"建议"

swiftui-pro 是给现代 iOS（iOS 26 / Swift 6.2）写的清单，直接套到我们这个"部署目标 iOS 15、 必须用 UIKit、单人自用不上架"的项目上会产生大量噪音。我明确没有采纳这些：

  • 「改用 @Observable / NavigationStack / 双参 onChange / Task.sleep(for:) / replacing(_:with:)」—— 全是 iOS 16/17+ API，我们的部署目标是 15。
  • 「去掉 UIKit 改用纯 SwiftUI」—— WKWebView / 画中画 / 后台音频 / PhotoKit 都是 UIKit 的活。
  • 「无障碍 / 上架合规」类 —— 单人自用，只留了真值得的那几条。

GCD、String(format:) 这类属于"风格整洁"而非"会出错"，我放在 P3 而不是混进前面。
