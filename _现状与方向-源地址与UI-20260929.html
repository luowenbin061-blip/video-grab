两件事，一句话各说完：
  • 源地址：数据已经存了一半 —— 媒体直链早就落盘了，缺的是「网页地址」。 现在它只活在内存里（SniffItem.page），下完就没了。补一个可选字段就能救回来。

1. 现在到底存了什么

数据存了吗在哪 / 说明
媒体直链（m3u8 / 分片清单） 已落盘 JobRecord.sourceURL（app/JobStore.swift:189）—— 建任务时把嗅到的地址存进去
Referer / UA 已落盘 JobRecord.referrer / .ua（:193-194，可选字段）。但不可靠：很多站不需要 Referer（存的是空串），或者它是接口地址而不是页面地址
Cookie 已落盘 :226 建卡那一刻的快照。（这是登录凭据，写磁盘的代价大于收益 —— 设计上故意的）
网页地址（你要的那个） 没落盘 SniffItem.page（app/BrowserModel.swift:14）只在内存里活一次。 它没被传进 downloads.add(...)（见 ContentView.swift:1416-1421 的调用点：只传了 url / referrer / ua / cookie）， 也没进 JobRecord → App 一关，永久丢失

★ 顺带确认：复制记录 那段文本（ContentView.swift:2459）里写的「地址：」用的是 sourceURL —— 也就是媒体直链，不是网页地址。直链通常带时效 token，过期就废，救不回东西。

2. 放在哪 —— 三个候选，我推荐 A + C

放哪成本可靠性 / 取舍
A JobRecord 加一个可选字段 page: String?
跟现有任务记录同一份 jobs 存档，不新增文件		 小
1 个字段 + 3 个调用点传参		 ★★★ 每个下载都留档。可选类型 → 老记录读进来是 nil，不会触发"落盘格式变更要写迁移"那条坑（这是这套代码一直用的做法）
B 不动代码，直接用现成的 referrer 兜 0 ★ 不可靠：Referer 为空时啥也没有；有值时也可能是接口地址。只能当兜底，不能当方案
C 压缩成品那条记录，继承原片的 page 最小 ★★ 只在"真可能后悔"的地方存。因为压完生成的是新任务（sourceURL = "local://compressed"）， 它自己拿不到原片的 page，必须显式带过来

推荐组合：A + C

A统一落盘在 JobRecord.page（来源单一，好维护）；
C压缩时把原片的 page 快照到压缩记录上 —— 这样你在压缩成品那张卡上就能直接跳回去， 不用去翻原片那条（原片很可能已经被你删了 —— 这正是当初那个问题的前提）。

3. 界面怎么给（关键：不加常驻按钮）

按你的一贯要求 —— 页面上东西越少越好，功能藏在入口后面。所以不加按钮，只加"翻开才看见"的东西：

位置给什么
任务详情卡（点开才看到）一个动作「回到原网页」→ 用内置浏览器打开它
「复制记录」的文本加一行「来源网页：…」（改 logText，一行的事）
压缩成品那张卡显示「原片来自：域名」+ 同一个「回到原网页」

4. 硬限制 —— 必须说清楚，别当成万无一失

存了网页地址也只是"大概率能救回"，不是保证：

  • 站上视频下架了 / 画质被换 → 救不回（这是最无法控制的）
  • 需要登录的站 → Cookie 故意不落盘，重下要重新登录
  • 页面是动态加载的 → 重开不一定还能嗅到同一条（尤其那种一次性的播放地址）
  • 重下拿到的是站上现在的版本，不是你当初下的那一版
  • 最要紧的一条："还原画质"这件事本身仍然做不到 —— 这条路是"重新拿一份原画质"， 不是"把压缩版修回去"。两者差别很大，别混。

2. 根因：一句话

每加一个功能，就"就地在最近的地方"塞一个入口 —— 没有人管"这东西该属于哪个家"。

三条证据：

  • 开关散在三处（同一个概念没有唯一的家）：
    设置里「下载保活 / 播放小窗 / 压缩时用小窗保活」 + ≡ 卡片底部「PIP 保活 / 共享给电脑」 + 工具箱里「桌面模式 / 无图模式」
    → 压缩保活在设置里，压画质入口在工具箱里，"压"这件事被切成两半放在两个地方
  • 工具箱破了对称：9 → 10 格
  • 设置长成一条平板：11 段平铺，没有"常用 / 高级"的分层

所以你"太多太多不满意"，大概率不是嫌它丑 —— 是每次想找一个东西都要先猜它在哪。 这个感觉是"归位规则缺失"直接造成的，不是配色和圆角能解决的。

3. 方向：三步，别一次全动

第 0 步 立「UI 冻结线」 —— 现在就该定，成本 ≈ 0

不用改一行代码，只是一条规矩。但不立它，债会一直涨：

  • 新功能一律走「复用已有入口 + 弹一张卡」
  • 不再往工具箱 / ≡ 卡片里加格子（要加就开第二页，代码注释里 v1.0.150 已经这么写了）
  • 新增「开关」→ 只能进设置，不许挂卡片底部

第 1 步 归位 —— 收益最大的一刀，成本：中

先定一张「什么放哪」的表，然后照着把散落的收回去：

类别家在哪
开关（开/关状态）设置。≡ 卡片底部那两个搬回去
动作（点一下做事）≡ 卡片
浏览器内工具工具箱
当次任务的界面弹出来的卡片（关掉就该结束）

★ 工具箱的「桌面模式 / 无图模式」可以留 —— 但要在界面上把它们明确成快捷方式， 而不是"第二个家"（否则同一个人又会找不到哪个才是真的开关）。

第 2 步 拆文件 —— 「以后改 UI 便宜」的前提，成本：中

ContentView 2785 行 按界面切开（主界面 / 嗅探面板 / 下载页 / 卡片动作 / 日志 / 图片查看器各归各）。 不拆的话，每次动 UI 都等于在 3000 行里翻 —— 这也是你觉得"改起来麻烦"的一部分原因。

第 3 步 审美统一 —— 放最后，成本：低

卡片间距 / 圆角 / 图标尺寸 / 文案长度统一；工具箱回到对称（收进设置 or 做第二页）。 这一层才是"好不好看"，前面三步是"好不好用"。顺序别倒。

4. 怎么开始（你只需要干一件事）

拿手机，把不满意的界面截图丢过来 —— 不用写文字描述，截图就是验收标准。
我按「改动半径 / 收益」排个序，一版改一处，不一次全动。
你说等以后再优化 —— 同意，不用现在动。这份清单先存着，等你哪天说「开始优化 UI」直接拿它开工，不用重新盘。
